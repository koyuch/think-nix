# AGENTS.md

Rules for AI agents working in **think-nix**, the flake that defines this laptop (NixOS host `think-nix`, user `koyuch`).
The user-wide rules (tool-install ladder, flake+direnv dev shells, latest versions) live in [agents/global.md](agents/global.md),
which Home Manager symlinks into every agent's global config. Treat that file as part of this repo too.
Human docs: [README.md](README.md).

## Layout

| Path | What it is |
| --- | --- |
| `flake.nix` | Inputs (`nixpkgs` = nixos-26.05, `nixpkgs-unstable`, home-manager release-26.05, plasma-manager, impermanence, NUR, nix-vscode-extensions), `nixosConfigurations.think-nix`, `templates.devshell` |
| `configuration.nix` | System: boot, btrfs + impermanence, services, `environment.systemPackages`, unfree allowlist |
| `home.nix` | Home Manager for `koyuch` (HM runs as a NixOS module, so there's no standalone `home-manager switch`) |
| `hardware-configuration.nix` | Generated by `nixos-generate-config`. Don't edit. |
| `agents/global.md` | Global agent instructions (out-of-store symlinked, so edits apply without a rebuild) |
| `agents/modes/` | Custom primary agent modes (`research`, `spec`), linked to `~/.config/{kilo,opencode}/agents` |
| `agents/skills/` | On-demand Agent Skills, linked to `~/.agents/skills` |
| `templates/devshell/` | `nix flake init -t ~/projects/think-nix#devshell` scaffold (flake + direnv + prek hooks) |
| `.pre-commit-config.yaml` | Repo hooks run by `prek`: hygiene, gitleaks, nixfmt, deadnix, shellcheck |
| `.forgejo/workflows/ci.yml` | CI on the homelab Forgejo runner: same hooks + gitleaks over full history + `nix flake check` |
| `fs-diff.sh` | Lists files on `/` that would be lost on reboot (impermanence audit) |

`/etc/nixos/*` are symlinks to this checkout, so a plain `sudo nixos-rebuild switch` (no `--flake`) also uses this repo.

## Where does a change go?

- **CLI/GUI tool for the user:** `home.packages` in `home.nix`, or better `programs.<x>.enable` when a HM module exists.
  `environment.systemPackages` is for system-level/base tools and anything root needs.
- **Service/daemon, kernel, hardware, groups:** `configuration.nix` (`services.*`, `virtualisation.*`, `programs.*`).
- **Newer version than stable has:** take it from `pkgs-unstable` (available in both modules via `specialArgs`/`extraSpecialArgs`),
  as the existing `(with pkgs-unstable; [ … ])` block does. Don't switch the whole system to unstable.
- **Unfree package:** add its `lib.getName` to `nixpkgs.config.allowUnfreePredicate` (stable `pkgs`).
  `pkgs-unstable` already has `allowUnfree = true`.
- **Project-specific tooling:** doesn't belong here. It goes in the project's own `flake.nix` (use the template).
- **Look up option names before writing them** instead of guessing:
  `nix eval .#nixosConfigurations.think-nix.config.<option>`, <https://search.nixos.org/options>,
  <https://home-manager-options.extranix.com/> (release-26.05), plasma-manager options.
  Release renames happen (e.g. `programs.git.settings`, `programs.ssh.settings` in 26.05), so prefer the current option name and
  fix deprecation warnings rather than silencing them.

## Validate & apply

Allowed without asking (no root, no system change). Run them from the repo dev shell
(`eval "$(direnv export bash)" && <cmd>`; avoid `nix develop -c`, it trips the auto-approve rules):

```bash
prek run --all-files                              # hooks (also run on every commit)
nix flake check                                   # evaluates the config + template
nixos-rebuild build --flake .#think-nix           # full build → ./result (gitignored)
nix store diff-closures /run/current-system ./result   # what would change
```

**New files must be `git add`-ed before any of these.** Flakes ignore untracked files ("path does not exist" errors).
Commit with the same prefix (`eval "$(direnv export bash)" && git commit …`), because the hooks need `gitleaks`/`nixfmt`/`deadnix` on PATH.

Requires the user's explicit approval:

- `sudo nixos-rebuild switch` / `boot` / `test`: run it after a green build and say why; the user approves via the
  sudo popup (fingerprint touch, password fallback). Don't just hand the command over.
- `nix flake update`: lockfile bumps are a separate `chore: update flake.lock` commit.
- Bumping release branches (`nixos-26.05` / `release-26.05`): keep nixpkgs, home-manager and the `follows` in sync.

## Danger zones (always ask, explain the risk)

- **`system.stateVersion` / `home.stateVersion`: never change.**
- **Impermanence:** `boot.initrd.systemd.services.btrfs-root-rotate` and `environment.persistence."/persist"`.
  A mistake here can make the system unbootable or lose state on next boot. A new stateful service usually needs its
  `/var/lib/<x>` added to `environment.persistence` (check with `fs-diff.sh`).
- **ESP is 256 MB** (shared with Windows): keep `boot.loader.systemd-boot.configurationLimit = 2`. Don't add kernels/initrd bloat lightly.
- **`users.mutableUsers = false`:** passwords only via `hashedPassword` (`mkpasswd -m sha-512`). A broken user config locks the user out.
- Firewall, SSH, Tailscale, sudo/PAM (fingerprint for sudo only; login/sddm stay password so pam_gnupg works):
  the machine is reachable over the network.

## Conventions

- **Formatting is enforced by `nixfmt`** (pre-commit hook + CI). Don't hand-format, and don't use alejandra.
  `hardware-configuration.nix` is excluded.
- Group packages under the existing `# --- Section ---` comments, with a short trailing comment for anything non-obvious.
- Comment *why* for workarounds (see the libvirt `credential.secret` comment) and date temporary disables.
- Commits: work directly on `main`, one logical change per commit, Conventional Commits with scope, e.g.
  `feat(packages): …`, `fix(boot,libvirt): …`, `chore: update flake.lock`. Commits are GPG-signed (pinentry may prompt).
- Remotes: Forgejo `homelab/think-nix` is the primary (`origin`). GitHub (`koyuch/think-nix`) and GitLab are mirrors.
- Repo is **public**: no secrets, tokens, or new private IPs/hostnames (gitleaks blocks the obvious ones).
